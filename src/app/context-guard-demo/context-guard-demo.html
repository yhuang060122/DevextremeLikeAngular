给自定义表格插槽 / 单元格模板里的 let-xxx 变量做 编译期类型守卫，消除 any。 运行时不会执行、打包后直接被擦除 —— 它只告诉 IDE / TS 编译器 <ng-template> 渲染时上下文对象的准确类型。 本页用「基金管理系统」的场景实测：普通版、泛型通用版、上下文扩展、插槽事件，全部可交互。

拆解

谁控制运行时数据？· 两条线各司其职，必须同步

① 运行时数据

[ngTemplateOutletContext] 在表格组件内部， 决定运行时传给模板什么值：单行 row → $implicit， 下标 → rowIndex。

② 编译期类型

ngTemplateContextGuard 只描述类型、不控制运行时数据。 告诉 TS 编译器这些变量的类型，让 IDE 补全和校验生效。

⚠️ 两条线必须对齐

类型和实际运行数据不一致 = 「类型说谎」：编译期看起来合法，运行时空值 / 缺字段。 本项目规范：上下文类型单独抽离，rowContext() 返回该类型，保证永远同步。

为什么插槽拿到的是单行 FundRow 而不是 FundRow[]？ 父组件传入数组 → 表格 @for 逐行迭代 → 每次循环把单行对象放入 $implicit → 插槽被执行 N 次，每次上下文是单条记录（点「新增基金」可验证）。

重点

坑 & 约束清单 · 项目落地踩坑

问题 说明
❗ 守卫只能在 Directive Component 不能挂载 ngTemplateContextGuard，必须单独写标记指令（如 appFundRowTpl）作为模板占位标记。
❗ 守卫是编译期 函数体不会运行，不要写业务逻辑；return true 固定写法。
❗ 类型与运行时必须对齐 Context TS 类型必须和 ngTemplateOutletContext 实际对象保持一致，否则类型说谎。
❗ 泛型参数对齐 指令泛型必须和守卫泛型保持同一个 TRow，否则类型推断失效。
❗ 不能忘记 track v21 的 @for 强制 track，表格循环必须加上。
对比

和相关概念的关系

概念 关系
toSignal / Zoneless 完全独立。Zoneless 只关心 Signal 更新驱动 UI；守卫只管 let-xxx 的 TypeScript 类型。两者互不影响。
@if / @for 内置控制流 内置自带类型推断，不需要手动写守卫；仅自定义插槽、自定义结构指令才需要。
DevExtreme dxCellTemplate 底层原理完全一致：内置指令携带 ngTemplateContextGuard，所以 let-data 自带行类型。
FAQ

常见问题

Q：可以直接在组件接收 TemplateRef，不写指令吗？

A：不行。ngTemplateContextGuard 只能挂载到 Directive。 没有标记指令，TS 无法推断模板上下文类型，let-xxx 变成 any。 变体：组件可以 @Input 显式接收 TemplateRef， 但守卫仍必须写在标记指令上。

Q：我想把整个数组传给插槽怎么做？

A：扩展上下文类型，加一个字段（本页演示 1 的 allRows）： FundRowTemplateContext 增加 allRows?: FundRow[]， 表格内部 rowContext() 同步构造，模板 let-all="allRows" 使用。 开启演示 1 的开关即可现场验证。

Q：Angular v21 是否废弃该 API？

A：没有废弃。新控制流（@if / @for）不替代自定义插槽场景，ngTemplateContextGuard 仍是官方标准方案。
