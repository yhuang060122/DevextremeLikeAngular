Angular 可扩展组件 · 插槽四件套

壳管布局，用户管内容

一个组件不该把内容写死 —— 它只负责给结构、间距、容器、位置， 里面放什么，交给调用方自由填充。下面用四种方式实现同一个 my-toolbar，从「最简单」到「最接近 DevExtreme dxo-* 配置指令」。

版本 A

ng-content 多插槽 · 静态投影 · 拿来就能用

组件模板里放几个 <ng-content select="[before]"> 占位， 调用方直接写 HTML 丢进来。限制：内容是"静态投影"，组件不能把 它挪走、延迟或二次渲染；内容生命周期属于父组件。

调用方怎么写
<my-toolbar-a>
  <button before (click)="add()">新增</button>

  <div after>
    <input (input)="onSearch($event)" placeholder="搜索">
    <select (change)="setStatus($event)"> … </select>
    <button (click)="refresh()">刷新</button>
  </div>
</my-toolbar-a>
现场效果（事件绑定完全正常）

✅ 组件侧几乎零逻辑：三个 ng-content + 一个 flex-1 撑开中间。适合：不需要自动溢出、不需要把项挪进菜单的简单排布。

版本 B

TemplateRef 模板插槽 · 拿渲染蓝图 · 可延迟 / 可复用

不用 ng-content 直接吞 DOM，而是通过 @Input 接收 TemplateRef。 模板只是蓝图，可以渲染多遍、稍后渲染、渲染到别的容器（比如溢出菜单） ——这是 ng-content 做不到的。

调用方怎么写
<my-toolbar-b [beforeTpl]="tplLeft"
              [afterTpl]="tplRight" />

<ng-template #tplLeft>
  <button (click)="add()">新增</button>
</ng-template>

<ng-template #tplRight>
  <input (input)="onSearch($event)">
  <button (click)="refresh()">刷新</button>
</ng-template>
现场效果
同一份蓝图，再画一遍（TemplateRef 可复用）
← 同一个 #tplLeft 被渲染到 toolbar 之外的第二个位置

✅ 组件可以先不画、等算完宽度，再把某些模板丢进「更多」下拉。 缺点：调用方要手动定义 #xxx，不如写一行行按钮自然。

版本 C

自动收集插槽指令 · 不限数量 · 最像 dx-item

一个轻注册指令 myToolbarItem 只负责「把自己的模板蓝图 上报给父组件」；父组件按位置遍历、用 ngTemplateOutlet 画出来。 想放几个就放几个，每个自带 before / center / after 位置标记。

调用方怎么写
<my-toolbar-c>
  <ng-template myToolbarItem="before">
    <button (click)="add()">新增</button>
  </ng-template>
  <ng-template myToolbarItem="before">
    <button (click)="batch()">批量操作</button>
  </ng-template>
  <ng-template myToolbarItem="center">
    <span>共 {{ count() }} 条</span>
  </ng-template>
  <ng-template myToolbarItem="after">
    <input (input)="onSearch($event)">
  </ng-template>
  <ng-template myToolbarItem="after">
    <button (click)="refresh()">刷新</button>
  </ng-template>
</my-toolbar-c>
现场效果（before ×2 + center ×1 + after ×2）
共 {{ count() }} 条 · {{ status() }}

✅ 这就是 dxi-data-grid-item 的极简原型：没有黑盒 JS-core、 没有桥接魔法，全部原生 Angular。指令只上报蓝图，父组件只管按位置画。

版本 D

dxo-toolbar 配置指令 · 不渲染 DOM · 控制 Grid 的内部组件

这是 DevExtreme dxo-* 的原生 Angular 版： <dxo-toolbar> 不画任何东西（纯配置指令），只把 position / visible / 插槽项 上报给宿主 my-grid； grid 把 toolbar 当作内部组件，按配置在表格上方/下方渲染。 连"toolbar 存不存在"都不写死在 grid 里。

调用方怎么写
<my-grid [rows]="gridRows">
  <dxo-toolbar [position]="tbPosition()"
              [visible]="tbVisible()">
    <ng-template myToolbarItem="before">
      <button (click)="add()">新增</button>
    </ng-template>
    <ng-template myToolbarItem="center">
      <span>共 {{ count() }} 条</span>
    </ng-template>
    <ng-template myToolbarItem="after">
      <input (input)="onSearch($event)">
      <button (click)="refresh()">刷新</button>
    </ng-template>
  </dxo-toolbar>
</my-grid>
现场效果 —— 用指令控制内部 toolbar
← 这三个按钮只改页面信号，grid / dxo-toolbar 自动响应
共 {{ count() }} 条 · {{ status() }}

✅ dxo-toolbar 是纯配置：不渲染 DOM，通过 ToolbarRegistry 收集内部项并注册给宿主；grid 把 my-toolbar-c 当内部组件，用 [items] 注入渲染。移除 <dxo-toolbar> 后 grid 就没有 toolbar —— 完全由调用方决定。
